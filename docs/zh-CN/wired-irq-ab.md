# 有线启动：EHCI 受控镜像对照

实机反馈：`1.txt`（候选）和 `2.txt`（对照）均在首包未到、连续返回 `03 03 03 00` 时失败，回退无线后两者都出现定时器池耗尽。本实验未恢复连接，后续见 [会话链路策略](wired-session-link.md)。下文记录原始实验步骤，不再建议重复测试这两个镜像。

## 目的及证据

已验收启动镜像使用主仓库 `9da89901` 和 IPHETH `ed797d2`，日志在 MFi 完成前已有 Ethernet RX/TX。后续失败为一个已提交的 Bulk IN、没有 RX 完成，Carrier 四字节响应被解码为 down。回归范围包括 EHCI 中断回收顺序及后续 RX/lwIP 调度修改。本实验单独验证中断顺序这一候选因素，不宣称已经确定硬件根因。

## 固件版本

产物位于 `output/wired-irq-epoch/`。`control/gui/` 保留前一版先 IAA 回收、后扫描的算法。`candidate/gui/` 在入口记录旧 IAA 对象集合，先扫描完成，再只回收旧集合。`candidate/headless/` 验证同一候选实现的 Headless 配置。两组 GUI 镜像使用相同冻结的应用、SDK、驱动和配置，行为差异限于 EHCI 中断函数，另有诊断策略字符串不同。候选实现没有恢复会用旧 IAA 提前回收新对象的原始不安全循环。

网络状态通过 `[wired-test] EHCI completion=iaa-before-scan` 或 `[wired-test] EHCI completion=epoch-after-scan` 标识版本，还会在清理前捕获最多八字节的 Carrier 状态、RX 计数、IPv6 状态和有界只读 EHCI 快照。构建包为每个镜像保留实际生成的 HCD 源码、补丁、配置、ELF、原始固件、打包 FIT 负载及哈希。

构建运行在独立的 native 源码副本中，不恢复、重置或写回共享 Windows 工作区配置。并行 OTA 工作不属于本实验，源码冻结后的修改不会自动纳入这些镜像，也不由本轮结果验证。不需要切换分支或创建 PR。

## 实机步骤

1. 先使用 `candidate/gui/d213-carplay-gui.img`。保持相同手机、USB 口、线缆和以太网连接，完整记录冷启动直到连接出画面，或第一次失败及清理结束；日志采集至少保留 60 秒。对照实验不删除信任记录。
2. 确认出现 `epoch-after-scan` 标记，记录 RX 完成是否出现、IPv6 是否有效、是否到达 stage 4/5 及是否出画面。初始验证集中于启动，音乐稳定性和流畅度另行验收。
3. 候选版本能连接时，重复冷启动和 USB 重连，再在相同条件下比较 `control/gui/d213-carplay-gui.img`。确认其 `iaa-before-scan` 标记并重复相同观察，每版三次有助于区分稳定差异与偶发启动。
4. 每次结果均保留镜像 SHA256 和完整日志。需要额外采样时仍可运行 `ipheth_status` 和 `usb_ehci_status 1`；网络超时清理前已有自动采样。

| 观察 | 解释 |
| --- | --- |
| 候选版稳定连接，对照版稳定失败 | 支持 EHCI 扫描/回调顺序参与回归；仍应保留日志，再判断完整根因。 |
| 两版均在首次 RX 前失败 | 本顺序修改不足以解决问题；根据 Carrier 原始响应和描述符进展排查设备激活或接收完成。 |
| 两版均连接，或结果不稳定 | 尚未隔离确定的坏提交，需比较冷启动/重连条件及附件状态。 |
| 候选版失败，对照版连接 | 候选版本不予验收，其行为需要继续调查。 |

## 软件验证边界

真实 HCD 测试覆盖 IAA 与 INT/ERR、旧/新对象集合、空旧集合、先扫描后回调、短包/零长度/完整/错误传输、控制状态阶段和缓存处理。去掉对象集合保护的负向对照按预期失败。GUI/Headless 构建及 IMG 边界/CRC 检查属于软件证据。有线启动、持续音乐、触摸、无线回归及 OTA 操作均需各自实机证据，测试完成前不宣称连接或性能已经改善。
